title: The desktop engine
description: Understand the state Open Web Desktop manages and how to connect a UI.

[`@owdproject/core`](https://github.com/owdproject/core) is the framework-independent TypeScript runtime at the center of Open Web Desktop. Each call to `createDesktop()` creates a desktop instance with its own state.

## What the engine manages

| Area | What it handles |
| --- | --- |
| Windows | Focus, stacking, moving, resizing and snapping |
| Applications | Registration, launch and process lifecycle |
| Workspaces | Switching desktops and defining the area available to windows |
| Commands and events | Command dispatch, lifecycle hooks and messages between applications |
| Sessions | Serializing and restoring supported desktop state |

## Create an instance

```bash
pnpm add @owdproject/core@4.0.0-alpha.4
```

```ts
import { createDesktop } from '@owdproject/core'

const desktop = createDesktop({
  workspaces: ['main', 'tools'],
  activeWorkspace: 'main',
  workarea: { x: 0, y: 0, width: 1280, height: 720 },
})

const unsubscribe = desktop.subscribe(snapshot => {
  console.log(snapshot.windows.length)
})

// Call unsubscribe when your UI stops observing the desktop.
```

A framework adapter bridges the engine and the framework's update mechanism. A shell uses that integration to render windows and controls. Apps, theme packages and optional services follow the conventions of their host.

For the public API and lifecycle expectations, see the [engine README](https://github.com/owdproject/core#readme) and [behavioral contract](https://github.com/owdproject/core/blob/main/docs/behavioral-contract.md). Check the contract at the version you consume when building an adapter.

Use [How OWD works](/architecture/technical-reference) to find the detailed guides for boot, state, components, dialogs, and shell identity.
